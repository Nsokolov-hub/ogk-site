# Полнота обхода остатков: 22.11.2026

Причины неполного результата предыдущего выпуска подтверждены на рабочей базе: после 120 страниц задачи источника удалялись; Скайклад остановился после одной неполной карточки, Диаэм — после перенаправления. Диаэм обновил разметку вариантов в категориях, которую прежний адаптер не читал. Вилакс обходился только по Welch, без химических реактивов. Положительные строки с неизвестным брендом терялись до очереди проверки менеджером.

Теперь лимит `max_pages_per_source` относится к одному этапу обработки. Обнаруженные разрешённые страницы сохраняются без прежних отсечений 120/200; источники обслуживаются по очереди. Ошибка отдельной карточки не стирает соседние страницы. Новые страницы получают собственные попытки загрузки. Разрешены только канонические GET-перенаправления 301/308 внутри объявленных открытых путей с повторной проверкой robots; отказ доступа/защита от ботов останавливает источник. Корень `/` больше не является разрешением на весь сайт.

Диаэм читает наличие каждой фасовки прямо из карточки модели в категории; остаётся поддержка старых таблиц. Вилакс включает открытый раздел реактивов, различает фасовку и единицу продажи и отделяет соседние карточки. Лабтех обходит общие списки без повторного обхода тех же производителей; положительные строки с неполными идентификаторами остаются на ручной проверке. Скайклад не требует формы заказа в каждой карточке, продолжает пагинацию и оставляет противоречивые фасовки на проверке. Новые бренды Химмед/Скайклад сохраняются для менеджера, а не публикуются автоматически.

Альгимед дополнительно обходит связанный складской список: на текущих открытых страницах распознаны 71 + 240 строк. Обе публикации датированы 29.10.2026: старые данные сохраняют эту дату и не становятся свежими после скачивания. ЦСДБ сохраняет прежнюю обработку явного склада СПБ с ручной проверкой идентификаторов.

HPLC, НеваРеактив и Лаверна проверяют реальные открытые разделы и карточки, а не только стартовую страницу. При проверке 22.11 просмотрены соответственно 13, 19 и 12 страниц: цены присутствуют, явного наличия нет. При локальной проверке ЛенРеактив отвечал 503; в новом рабочем обходе доступ восстановился, адаптер проверяет открытые страницы магазина. Статус больше не закрепляет временный отказ как постоянное свойство источника. Эти ограничения показываются в источниках. Цена/кнопка заказа сами по себе не становятся остатком. Обход ограниченной выборки у источника без складского фида не выдаётся за полный сбор его остатков.

CRM показывает текущий обход, оставшиеся страницы и отдельные счётчики сохранённых/свежих предложений, точных фасовок и ручной проверки. Исходные поставщики остаются во внутренних данных; клиентская выгрузка и витрина их не раскрывают. Схема БД и финансовые записи не меняются. Настройки интервала (3 дня после завершения), паузы и срока свежести сохраняются.

Проверки включают продолжение более 120 страниц после перезапуска с лимитом 2 за этап, отсутствие отсечения 200 ссылок, справедливый порядок источников, частичную карточку Скайклада, противоречивые фасовки, границы карточек Вилакс, канонические перенаправления и запрет перехода в закрытые пути, PostgreSQL и закрытый каталог CRM. Реальные HTML для анализа находятся вне репозитория: `/private/tmp/parser-nov22/` и `/private/tmp/parser-other-nov22/`.

Для принудительного нового обхода при выкатке: завершить штатный worker, сохранить прежний `competitor_run`/`competitor_results` для диагностики, сбросить только состояние технического обхода и отметку `finishedAt`, затем запустить один worker. Не запускать синхронный CLI параллельно с worker: разделяемая очередь пока не имеет блокировки нескольких обработчиков.
