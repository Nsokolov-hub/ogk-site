# Проверенный SKU и ограниченный SEO-пилот

## USP 1235831

Проверенная позиция: **Enoxaparin Sodium for Bioassays, USP Reference Standard**, производитель USP,
фасовка **1 ampoule**. Каталожные номера `1235831` и `1235831-1AMP` относятся к базовой позиции и её фасовке.
Источник: [каталог Sigma-Aldrich](https://www.sigmaaldrich.com/BE/en/product/usp/1235831).
Sigma-Aldrich обозначает канал каталога, не другого производителя этого стандарта.

Команда работает только с двумя существующими slug и не создаёт демонстрационные товары:

```sh
python -m app.catalog.cli enrich-usp-enoxaparin
python -m app.catalog.cli enrich-usp-enoxaparin --apply
```

Сначала сохранить JSON-предпросмотр и резервную копию БД. Проверить `errors: []`, ID обеих карточек и
изменения фасовки. При конфликте базового номера в одном бренде или неоднозначной фасовке применение
отказывается менять обе карточки. Повторное применение не создаёт новых товаров, фасовок или записей аудита.

Сохраняются product/packaging ID, URL, brand ID, CAS, документы, наличие, условия хранения и история
заявок. Полный номер фасовки передаётся в новую заявку с количеством упаковок: **9 × 1 ampoule** означает
`quantity=9`, `unit=pack`, `packaging=1 амп.`, `catalog_number=1235831-1AMP`.

Основная карточка — `/product/usp-1235831/`. Вторая старая карточка остаётся доступной, объясняет канал и
ссылается на основную; её canonical указывает на основную. После проверенного обогащения поиск возвращает
одну основную карточку по обоим номерам, включая `USP1235831` и `USP1235831-1AMP`. Другие товары с одинаковым
CAS не объединяются. Неоднозначные результаты и одиночные неточные совпадения требуют выбора пользователя.

После apply команда отправляет в поиск только эти карточки и сбрасывает кеш каталога. Проверить оба старых
URL, canonical, поиск обоих артикулов, строку списка `USP 1235831-1AMP 9`, выбор ампулы и состав заявки до
отправки. Исторические строки заявки остаются снимком введённых на тот момент данных.

## Пилот 20–50 реальных страниц

```sh
python -m app.catalog.cli quality-pilot --brands usp,edqm --limit 25
python -m app.catalog.cli quality-pilot --brands usp,edqm --limit 25 --apply
```

Отчёт показывает опубликованные и разрешённые к индексации страницы брендов, кандидатов, источник данных,
полноту, наличие уникального описания, решение и недобор до лимита. Это покрытие каталога на сайте,
**не фактическое покрытие индекса Яндекса или Google**. Данные `seed` исключены. Кандидат должен иметь
реальное название, фасовку и CAS/характеристику колонки либо явно проверенную идентичность производителя.
Явный запрет индексации менеджером сохраняется. Уже индексируемые кандидаты получают действие `monitor`.

Применение использует существующий ручной override только для выбранных кандидатов в пределах отчёта.
Глобальный порог полноты, остальные бренды и весь массив CAS не меняются. Не создавать уникальные
описания, технические характеристики или научные утверждения без проверенного источника производителя.

Для каждой выбранной страницы фиксировать URL и исходный уровень: индексирование/причину исключения в
Webmaster/Search Console, показы, запросы, клики, целевые обращения, коммерческие предложения и подтверждённые
оплаты. Сравнивать результаты после повторного обхода; отправка в Sitemap/IndexNow сама по себе не доказывает
индексирование или позиции. Полезный результат пилота — релевантный запрос и его коммерческий исход.

## Привлечение при лимите 50 000 ₽ в месяц

Первый контролируемый эксперимент: до **15 000 ₽ за 14 дней**, оставшиеся **35 000 ₽** не расходовать автоматически.
Запуск рекламы и платёжные действия в эту реализацию не входят. Расход ограничивать в кабинете фактическим
доступным способом и проверять ежедневно: дневной бюджет сам по себе не обещает строго равномерных списаний.

- Группа точного спроса: `USP 1235831`, `1235831-1AMP`, полное название стандарта и закупочные формулировки.
  Посадочная — проверенная основная карточка с выбранной ампулой.
- Отдельно небольшой список других существующих артикулов USP/EDQM после проверки реальной возможности
  расчёта у поставщиков. Один покупатель Enoxaparin — гипотеза спроса, а не доказательство лучшей ниши.
- Раздельные UTM для групп/объявлений. В отчёте связывать расход → уникальное целевое обращение → КП →
  оплату. Клики по кнопке и статус «Запрошено» не считать покупкой.
- Просматривать поисковые фразы и стоимость обращений, исключать нерелевантный спрос. Не расширять охват
  только ради числа визитов. При отсутствии целевых обращений после расхода лимита остановить эксперимент,
  проверить запросы, страницу, доставку форм и работу менеджера перед новым бюджетом.

Допустимая стоимость клиента рассчитывается из подтверждённой маржи и повторных покупок, которых пока нет
в данных. Не назначать целевой ROAS или гарантированную конверсию произвольно. На маленькой выборке оценивать
сначала качество обращений и исправность измерений; A/B-тест цвета кнопок не даст надёжного ответа.
