# Бэкенд сайта ogk-chem.ru

FastAPI + SQLAlchemy 2 + PostgreSQL 17 + Meilisearch, тот же стек и те же приёмы, что в «Реактив CRM». Здесь:

- каталог (ТЗ 5): бренды, категории, субстанции, товары, фасовки, документы, связи; полнота карточек и уровневая индексация;
- поиск (ТЗ 6) на Meilisearch: подсказки, выдача, страницы категорий с фильтрами и счётчиками, поиск по списку и файлу;
- импорт прайсов и первичная загрузка выгрузки ассортимента (ТЗ 9.5, 9.6), перечни подконтрольных веществ (5.2.1);
- реестр производителей из CRM (поток F5), корзина гостя по cookie (RFQ-01);
- приём заявок с форм сайта и их доставка в CRM (поток F1, ТЗ 7 и 9).

## Каталог и поиск

- Источник правды — PostgreSQL (`app/catalog/models.py`). Индекс Meilisearch производный: любое изменение товара ставит `needs_index`, воркер каждые несколько секунд отправляет такие товары в индекс пачками по 1000. Полная переиндексация без простоя — новый индекс, заполнение, обмен местами со старым (`python -m app.catalog.cli reindex`).
- Движок спрятан за `app/catalog/search/engine.py`; Meilisearch знает только `meili.py` (HTTP через httpx, без SDK).
- Порядок выдачи (SRCH-04): точный кат. № или CAS, включая номера фасовок и альтернативные CAS → брутто-формула → полнотекст; при равенстве выше товары в наличии и с полной карточкой. Точные совпадения ищутся отдельным запросом-фильтром и ставятся первыми. Номера и CAS ищутся без опечаток; пустая выдача повторяется в другой раскладке; синонимы RU ↔ EN — из справочника субстанций.
- Счётчики фильтров — «с учётом остальных фильтров»: по запросу на каждый выбранный фильтр в одном multi-search.
- Публичное API — `/api/v1/public/catalog/*`, `/products/{slug}`, `/brands/*`, `/substances/*`, `/search/*`, `/cart` (`app/catalog/routes.py`). Схемы — `app/catalog/schemas.py`; контракт — `openapi.json` (витрина генерирует из него типы, CI сверяет).
- Лимит поисковых запросов — `SEARCH_RATE_PER_MINUTE` с адреса, глубина страниц — `SEARCH_MAX_PAGE` (NFR-05).

Замеры на выгрузке ассортимента (1,67 млн карточек, ноутбук, Docker): движок p50 9 мс, p95 14 мс; через API подсказки p95 59 мс, страница категории с фильтрами p95 181 мс, карточка p95 48 мс.

## Импорт прайсов

```bash
# предпросмотр: сколько создастся, обновится, ошибок и конфликтов — товары не меняются
python -m app.catalog.cli import price.xlsx --source price --dry-run
python -m app.catalog.cli import price.xlsx --source price
python -m app.catalog.cli batches                         # журнал партий
python -m app.catalog.cli issues <batch> --xlsx out.xlsx  # ошибки и конфликты партии в xlsx
python -m app.catalog.cli rollback <batch>                # откат партии
```

- Источник — шаблон колонок (`app/catalog/importer/sources.py`): `assortment` — выгрузка ассортимента 17.10.2026, `price` — прайс поставщика. При первом использовании шаблон сохраняется у источника в базе (IMP-02).
- Строка: бренд по реестру написаний, нормализация кат. №, проверка CAS по контрольной цифре, разбор фасовок «100 мг | 1 г», категория по правилам (`importer/rules.py`) — остальные без категории, но сразу на сайте и в поиске (IMP-03). Номер с фасовкой на конце («CS-T-60514-5MG») становится фасовкой товара «CS-T-60514», полный номер остаётся у фасовки и ищется.
- Бренд + нормализованный кат. № находят товар: новый создаётся, существующий обновляется, кроме полей из `manual_fields`; тот же номер с другим CAS — конфликт, товар не меняется (IMP-04, IMP-05). Позиции, исчезнувшие из полного источника, остаются «Под заказ».
- Партия обрабатывается пачками по 5 000 строк, каждая в своей транзакции; журнал, выгрузка ошибок, откат (IMP-06). Скорость: 500 000 строк — около 2 минут (IMP-07).

### Первичная загрузка выгрузки (ТЗ 9.6)

```bash
docker compose run --rm -v "$HOME/Downloads/каталог товаров:/import:ro" api \
  python -m app.catalog.cli import /import/1.xlsx /import/2.xlsx /import/3.xlsx /import/4.xlsx /import/5.xlsx --no-index
docker compose exec api python -m app.catalog.cli reindex
```

Из выгрузки берутся производитель, кат. №, CAS, фасовки, название на латинице (это название по каталогу производителя) и из характеристик — только брутто-формула и молекулярная масса. Собственные позиции источника, его ссылки и ID, цены, наличие, разделы, остальной текст характеристик и описания не читаются и не хранятся; всё — «Под заказ». Переведённые названия источника хранятся внутри (`source_name`) и нигде не показываются: ни в API, ни в индексе поиска; такая карточка называется по субстанции или «бренд + кат. №». Тест `tests/catalog/test_source_data.py` проверяет, что ссылок, ID, бренда и текста источника нет ни в одной таблице каталога, ни в API, ни в индексе. Новые производители становятся брендами без страницы и попадают в журнал на сверку с реестром CRM. Ниша первой очереди — `--brands "USP,LGC Dr. Ehrenstorfer,Clearsynth,Merck,Waters"`.

Результат на выгрузке 17.10.2026: 2 434 755 строк за 10,5 минуты → 1 668 465 карточек и 2 млн фасовок, 287 новых брендов, 127 конфликтов CAS, 10 787 неверных CAS (позиции загружены без CAS). По разделам: реактивы 957 тыс., биохимия и биотехнологии 434 тыс., стандартные образцы 168 тыс., хроматография 72 тыс., оборудование 18 тыс., посуда 10 тыс., без категории — 10 тыс. Формула и молекулярная масса — примерно у трети позиций (ABCR, Acros и др.). Индекс: 5 минут, 9 ГБ.

### Подконтрольные вещества (ТЗ 5.2.1)

`python -m app.catalog.cli controlled перечни.xlsx` — колонки «Перечень» (681/964), «Название», «CAS», «Синонимы» через «;». Загрузка заменяет перечни и перепроверяет весь каталог: совпадение по CAS скрывает позицию, совпадение только по названию — тоже скрывает и ждёт решения химика (`controlled_state = review`); решения химика (`confirmed`, `cleared`) перепроверка не трогает.

### Реестр производителей из CRM (поток F5)

Воркер раз в сутки загружает изменения реестра (`GET /api/v1/integrations/site/manufacturers` CRM, тот же токен и подпись, что у F1); сразу — `python -m app.catalog.cli sync-brands`. Производитель CRM привязывается к бренду с тем же написанием или становится брендом без страницы; написания пополняют реестр импорта; слияние в CRM переносит товары на основной бренд и ставит 301 со страницы старого.

### Настройки каталога

`python -m app.catalog.cli setting <ключ> [JSON]` — `index_threshold` (порог индексации, 70), `completeness_weights`, `hide_controlled`, `feed` (разделы и бренды фида). После смены порога или скрытия подконтрольных каталог пересчитывается и уходит в индекс. Запросы без результатов — `python -m app.catalog.cli misses` (SRCH-12).

Структура каталога — `python -m app.catalog.cli seed --content-only`: дерево категорий с текстами RU/EN (в том числе «Биохимия и биотехнологии»), страницы брендов, субстанции. Это нужно и в production до первого импорта. Без ключа добавляются 413 тестовых позиций — только для разработки и staging.

Категории по правилам (`importer/rules.py`): по бренду, затем по словам названия — антитела, рекомбинантные белки, пептиды, ИФА у реактивных брендов и брендов без правила уходят в «Биохимию и биотехнологии». После правки правил: `python -m app.catalog.cli recategorize` раскладывает импортированные позиции без категории (`--all` — и остальные импортированные); категории, поставленные людьми, не трогаются.

## Как идёт заявка

1. Витрина отправляет `POST /api/v1/public/requests`: `multipart/form-data` с JSON формы в части `payload` и необязательным файлом в части `attachment`, заголовок `Idempotency-Key` — UUID отправки.
2. API проверяет поля, как формы (ИНН с контрольной суммой, телефон E.164, согласие), вложение (XLSX, CSV, PDF, DOCX до 10 МБ, тип — по содержимому) и антиспам (скрытое поле, время заполнения, лимиты по адресу, SmartCaptcha только при подозрении).
3. В одной транзакции сохраняются заявка с номером `S-2026-000123`, позиции, вложение, источник визита (cookie `ogk_attr`, `_ym_uid`, `_ga`) и три задачи outbox: доставка в CRM, письмо клиенту, письмо на order@. Ответ клиенту уходит только после фиксации.
4. Worker (`python -m app.outbox.worker`) доставляет заявку в CRM: подпись HMAC, `Idempotency-Key` = id заявки, повторы через 1, 5, 15, 60 минут и дальше раз в час до 24 часов. Каждая попытка пишется в `delivery_attempts`.
5. Заявка не в CRM через 15 минут — алерт в Telegram (только номер и ошибка) и письмо на `ALERT_EMAILS` с полным составом. CRM отклонила заявку (400, 409, 422) — алерт сразу, повторы прекращаются; 401 или 403 — алерт сразу, повторы продолжаются.

| Ответ CRM | Что делает сайт |
|---|---|
| 200, 201 | Заявка доставлена, сохраняются id и номер CRM |
| Таймаут, сеть, 5xx, 429 | Повтор по расписанию |
| 401, 403 | Алерт сразу, повторы продолжаются |
| 400, 404, 409, 413, 422 | Алерт сразу, статус `failed`, переотправка вручную |

Пока `CRM_DELIVERY_ENABLED=false`, заявки копятся в очереди, а отдел продаж получает их письмом. Когда доставку включат, очередь уйдёт в CRM сама.

## Запуск для разработки

```bash
cp .env.example .env
docker compose up -d --build
npm run dev
```

API — <http://127.0.0.1:8001/api/docs>, письма — <http://127.0.0.1:8025>. Витрина проксирует `/api/v1/*` на `API_ORIGIN`.

Без Docker:

```bash
cd backend
uv venv .venv --python 3.13 && VIRTUAL_ENV=.venv uv pip install -r requirements-dev.lock
DATABASE_URL=postgresql+psycopg://… .venv/bin/alembic upgrade head
DATABASE_URL=… .venv/bin/uvicorn app.main:app --port 8001
DATABASE_URL=… .venv/bin/python -m app.outbox.worker
```

## Проверки

```bash
cd backend
.venv/bin/ruff check . && .venv/bin/mypy app tests
.venv/bin/python scripts/export_openapi.py --check     # openapi.json совпадает с кодом
DATABASE_URL=sqlite:// .venv/bin/pytest -q
# на PostgreSQL и настоящем Meilisearch (тесты поиска с контрольными примерами ТЗ 6)
TEST_DATABASE_URL=postgresql+psycopg://… TEST_MEILI_URL=http://127.0.0.1:7700 TEST_MEILI_KEY=… DATABASE_URL=sqlite:// .venv/bin/pytest -q
```

После изменения схем API: `python scripts/export_openapi.py`, затем в корне `npm run api:types`.

Тест `tests/test_contract.py` проверяет тело, которое сайт отправляет в CRM, по схеме из `contracts/crm-f1.json`. Схема закреплена из `docs/openapi.json` CRM. Если CRM намеренно меняет контракт, перезакрепите её:

```bash
python3 backend/scripts/pin_crm_contract.py ../my-crm-project/docs/openapi.json
```

## Эксплуатация

```bash
docker compose exec api python -m app.cli status        # сводка по статусам и очереди
docker compose exec api python -m app.cli undelivered   # заявки, которых нет в CRM
docker compose exec api python -m app.cli resend S-2026-000123
```

Подключение к CRM: в CRM выпустите токен (`python -m app.integrations.site_tokens create --name production`), впишите адрес сервера сайта в `SITE_INTEGRATION_ALLOWED_IPS` CRM, а здесь заполните `CRM_URL`, `CRM_TOKEN`, `CRM_SIGNING_SECRET` и включите `CRM_DELIVERY_ENABLED=true`. Подробно — `docs/site-integration.md` в репозитории CRM.

После изменения зависимостей в `pyproject.toml`:

```bash
uv pip compile pyproject.toml -o requirements.lock
uv pip compile pyproject.toml --group dev -o requirements-dev.lock
```
